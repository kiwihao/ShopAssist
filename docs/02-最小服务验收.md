# 第 2 步验收记录

日期：2026-11-01。本轮完成最小服务和真实数据库连接，不包含模型调用和业务问答。

## 已实现

- 独立 Java 21 / Spring Boot 3.5.16 服务，Maven Wrapper 3.9.12。
- Compose 启动 PostgreSQL 17 + pgvector 0.8.2，持久化数据卷，端口仅绑定本机。
- GET /api/health：实际执行 SELECT 1 和扩展版本查询；失败返回 503。
- 请求 ID、探测耗时和异常类型日志；失败响应不输出凭据或堆栈。
- README 启停说明与 scripts/check-health.ps1 检查脚本。

## 实际验证结果

| 检查 | 结果 |
| --- | --- |
| docker compose up -d --wait | 容器 Healthy |
| SQL 查询 pg_extension | vector 版本 0.8.2 |
| 正常访问 /api/health | HTTP 200，database UP，pgvector 0.8.2 |
| docker compose stop postgres 后访问 | HTTP 503，database DOWN，pgvector UNKNOWN |
| 恢复数据库后再次执行检查脚本 | HTTP 200，检查通过 |
| server 下执行 .\mvnw.cmd -B -ntp clean package | 停止占用 JAR 的测试 Java 进程后 BUILD SUCCESS |

这是实际 HTTP / 数据库集成冒烟验证；本轮没有新增 JUnit 测试，Maven 输出 No tests to run，不能把打包成功称为全部自动化测试通过。
缺失扩展的 MISSING 分支已实现，未单独删除扩展做运行测试。

## 遇到的问题

运行中的 Java 进程锁定 JAR，Windows 下 clean 失败。停止本次测试进程后重新执行构建通过；操作顺序已补进 README。未停止其他项目进程。

## 交付时状态

数据库仍运行并保留数据卷；本次测试启动的 Java 进程已停止，方便用户按 README 在自己的终端启动。
