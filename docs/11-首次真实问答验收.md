日期：2026-11-01。本轮验证本机 8081 Java 服务、容器 PostgreSQL/pgvector、容器 Ollama BGE-M3 与真实 DeepSeek 聊天调用。没有读取、输出或保存 API Key。

## 运行与证据

在项目根目录执行：

```powershell
Set-Location D:\study\codex\program_two
.\scripts\check-retrieval.ps1 -RetryFailed
.\scripts\check-qa.ps1
```

第二条命令会产生聊天 API 调用费用。脚本兼容 Windows PowerShell 5.1，中文脚本保存为 UTF-8 BOM。

检索记录在 `.runtime/retrieval-results.json`；问答请求、回答、引用、复核检索结果及逐例判定在 `.runtime/qa-results.json`。目录已忽略，不包含密钥。重复执行会覆盖这两个本地结果文件。

两款商品各 6 个片段状态为 READY。模型为 bge-m3:567m，1024 维；Ollama 模型 ID 为 790764642607。尺寸检索均首先命中对应商品的“尺寸与电脑收纳”。本轮没有跨商品引用。

有引用的回答还逐条检查了商品 ID、片段 ID、正文、文档名、版本、标题与行号，均匹配同一问题独立复检的 top5 检索结果。服务端同时只允许引用当次检索证据中的 ID；伪造来源的拒绝路径由单元测试覆盖。独立复检要求期间不更换有效文档版本。

故障路径使用本地模拟上游返回 HTTP 503，客户端得到 CHAT_HTTP_503；服务层测试确认将异常传出。这一项是自动测试验证，未中断真实 DeepSeek 服务进行故障注入。
