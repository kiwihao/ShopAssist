# 智谱 429 排错与重试修复

日期：2026-11-01。

用户提交的 IDEA 日志显示：服务启动成功，Embedding 接口返回 upstreamStatus=429、attempts=2，入库任务为 INDEX_FAILED / MODEL_HTTP_ERROR。现有日志未保留供应商业务码，尚不能确定具体根因。

后续结果已确认：用户运行新版脚本得到 INDEX_FAILED / MODEL_HTTP_ERROR_1113。官方定义为账户欠费；当前阻塞转为核对所用标准 API 账户的余额或适用资源包。尚未查看用户账户详情，不推断具体余额或要求充值固定金额；暂停重复模型请求，待账户可用后重试原任务。

依据 [智谱官方错误码](https://docs.bigmodel.cn/cn/api/api-code)，429 同时覆盖欠费、速率限制、模型繁忙、使用额度和 Key 类型等错误，因此不能仅凭 HTTP 429 建议充值或不断重试。

本次修复：

- 仅提取并记录数字业务码，任务错误码形如 MODEL_HTTP_ERROR_1113；不记录原始错误正文或密钥。
- 对 1302 / 1305 及 5xx 最多额外重试一次并等待，其他 429 不自动重试。
- 尊重有限 Retry-After 秒数，较长等待交还用户，不立即重试。
- 检索脚本新增 -RetryFailed，显式重试原任务，无需删除资料或新建任务。

操作：

1. 在 IDEA 停止并重新运行 DemoApplication，使客户端修改生效。
2. 在项目根目录执行 `.\scripts\check-retrieval.ps1 -RetryFailed`。
3. 如果失败，查看脚本中的 MODEL_HTTP_ERROR_数字，或 IDEA 的 upstreamCode=数字。

| 业务码 | 官方含义/排查方向 |
| --- | --- |
| 1113 | 账户欠费：检查标准 API 余额状态 |
| 1302 | 账户速率限制：检查请求频率与模型并发权益 |
| 1305 | 模型繁忙：稍后再试 |
| 1308 / 1310 | 使用额度上限：查看重置时间 |
| 1311 / 1315 | 模型权限或 Key 类型：核对所用 API 产品 |

上述为可能分支，尚未确认用户账户属于哪一项。不更换项目技术栈，不要求购买课程或盲目充值。

新增本地 HTTP 测试覆盖欠费/额度/权限不重试、数字码提取、限流最多一次重试、未知码与较长 Retry-After 不盲目重试。真实接口根因需要重启后重新取得业务码。
