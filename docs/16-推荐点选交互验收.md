# 推荐入口：点选优先

日期：2026-11-02。根据“对话输入繁琐、容易漏条件”的反馈调整前端，不改筛选接口、数据模型或框架。

## 当前交互

- 商品问答欢迎页新增“点选条件帮你挑”入口，原侧栏入口保留。
- 推荐首屏直接选择150元以内、200元以内、不限预算或自定义范围，不要求先输入自然语言。
- 电脑与清洗要求默认“不作要求”，底部明确显示“电脑适配不限、清洗方式不限”；不是保证商品适配所有电脑或清洗方式。
- 选择放电脑才展开长、宽、厚；有缺项、非正数、超过200cm、精度过高或预算矛盾时提示并禁用提交。Java 原有校验仍保留。
- 底部条件摘要与查找按钮固定在滚动区外，提交前始终可核对。
- 自然语言识别和其他硬性要求改为折叠入口。已填写但未识别的文字会阻止查找，避免静默丢弃文字条件；识别结果与 Agent 带入的条件仍可在控件中核对。
- 手机推荐页暂收起商品目录，保留功能切换，给条件和结果更多空间。

“不限预算”明确由用户点击，映射为价格下限0元、无上限，适用于当前商品表非负价格约束；没有暗中设置预算。自定义与自然语言仍保留严格小于/大于的预算边界。

## 实际验证

1. 点选150元并确认：真实筛选仅返回BP-B；请求日志为 /api/recommendations，没有 /understand 模型识别请求。
2. 选择放电脑后未填尺寸、只填长宽：提交禁用，直接提示缺失尺寸。
3. 150元、35×24×2cm：真实返回NO_MATCH；改成200元后只返回BP-A，没有自动放宽条件。
4. 文字输入“预算不到129元，推荐背包”：识别前提交禁用，识别后自定义范围显示“低于129”，没有变成“129以内”。
5. 1440×1000桌面、390×844和320×740手机视口：无页面横向溢出，底部按钮可见，文字输入默认折叠。
6. TypeScript类型检查和Vite构建通过，浏览器无未捕获脚本异常。

## 工单理解补充

按钮防连点只能减少当前页面的重复操作，不能覆盖多窗口、绕过页面直接请求和网络重试。同一草稿确认由事务、草稿唯一约束与幂等键共同保证只有一张正式工单，重复请求返回原工单；不是先保存多张再使其他工单失效。

另一份新草稿可以创建独立工单，不会被“同草稿唯一”约束拦截。该功能不是基于文本相似度的全局问题去重。
