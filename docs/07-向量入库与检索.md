# ShopAssist：向量入库与商品检索

日期：2026-11-01。已实现模型客户端、向量入库和纯向量检索。真实智谱账户调用等待本机配置新密钥后验证；当前还没有最终答案生成。

## 1. 启动与真实接口验收

停止旧服务，在 Windows PowerShell 5.1 或 PowerShell 7 终端执行。AsSecureString 会遮盖输入，密钥无需写入命令历史或文件。

```powershell
Set-Location D:\study\codex\program_two\server
.\mvnw.cmd package
$env:BIGMODEL_API_KEY = [System.Net.NetworkCredential]::new('', (Read-Host '请输入新生成的智谱 API Key' -AsSecureString)).Password
java -jar target\ecommerce-rag-demo-0.0.1-SNAPSHOT.jar
```

在项目根目录的另一个 PowerShell 5.1 或 7 终端执行：

```powershell
Set-Location D:\study\codex\program_two
.\scripts\check-retrieval.ps1
```

该脚本会调用你配置的真实模型：上传两份商品样例、等待解析、提交向量化任务、等待 READY，再分别检索尺寸问题。请求与召回结果保存至 .runtime/retrieval-results.json。
脚本通过共享 .NET HttpClient 兼容两种 PowerShell，不依赖 -Form、-SkipHttpErrorCheck 或 utf8NoBOM 编码选项。含中文脚本使用 UTF-8 BOM，避免 Windows PowerShell 5.1 按系统代码页误读。
脚本只检查能返回本商品证据，不证明相关性或 Recall 达标；需要人工检查是否召回正确尺寸说明。
如果 180 秒内未结束，脚本提示查看任务状态，不会擅自创建新版本反复提交。

没配密钥时服务仍能启动和解析文档；提交向量化返回 503 / MODEL_NOT_CONFIGURED。Java 不会自动读取根目录 .env。聊天模型 glm-5.3-flash 尚未接入。

若任务曾 INDEX_FAILED，先查看错误码，解决问题后执行 `.\scripts\check-retrieval.ps1 -RetryFailed`，对已有任务显式重试一次。未加此选项时，脚本遇到已有 INDEX_FAILED 会停止。

## 2. 接口与状态

- `POST /api/admin/ingestion-jobs/{id}/index`：不需要请求体，202 返回当前任务。仅 PARSED / INDEX_FAILED 可进入队列；重复提交排队、处理中或 READY 的任务不重复调用模型。
- `POST /api/retrieval/search`：JSON 输入如下，返回 requestId、matches、模型/维度和耗时；matches 含片段 ID、商品、文件名、版本、标题、行范围、原文和 similarity。

```json
{"productId":"BP-A","query":"电脑仓尺寸是多少？","topK":3}
```

topK 默认 5，范围 1～10；问题不超过 1000 个 Unicode 码点，并受模型客户端 3000 UTF-8 字节保守上限约束。未知商品返回 404，非法参数 400。模型故障返回明确模型错误，不包装成空检索结果。

状态：

`PARSED → INDEX_PENDING → INDEXING → READY / INDEX_FAILED`

解析失败仍使用 FAILED。INDEX_FAILED 保留分块，可显式重试。任务详情新增 active 和 active_version_id：READY 表示该版本索引完成，active 才表示该文档当前有效版本。旧版本可 READY 但不再 active。

启动时 INDEXING 恢复为 INDEX_PENDING；仅支持单应用实例，不能运行多个进程共享本库。数据库不可用导致失败状态也无法落库时，恢复数据库并重启后重新领取；本阶段没有分布式租约或全自动故障恢复。

## 3. 模型调用与数据一致性

依据 [智谱 Embedding-3 官方示例](https://docs.bigmodel.cn/cn/guide/models/embedding/embedding-3)，请求标准 /embeddings 接口，模型 embedding-3，明确传 dimensions=1024。每批最多 16 个片段，输入为标题路径加原文。

客户端检查返回数量、index 唯一性、1024 维、数值类型、有限值和非零向量；按 index 对齐返回顺序。长输入不静默截断；超过保守字节上限提示缩短问题或进一步分块。该限制不是精确 token 计数。

连接超时 5 秒、读取超时 30 秒。网络异常和 5xx 最多额外调用一次；429 仅对已识别的 1302/1305 暂时性错误允许一次重试，欠费、额度、权限及未知 429 不盲目重试。HTTP 重试默认等待 1 秒；上游 Retry-After 为 0～5 秒时遵循该值，超过上限或为日期时交由调用方稍后处理。401 等权限错误和非法响应不重试。
响应体仅提取 4～6 位数字业务码，日志和任务错误码可见该值；原始正文、供应商 message 和密钥均不记录。错误响应附本地维护的排错提示。日志记录批量大小、尝试次数、耗时与实际返回的 token 数；未核验计费价格，不报告费用或性能收益。

V3 迁移新增 chunk_vectors（vector(1024)）和文档 active_version_id：

1. 读取已有分块，调用 Embedding，暂存在内存。
2. 所有批次成功后，在同一数据库事务保存全部向量、标记 READY、切换有效版本。
3. 任一批次失败不写半套向量，不切换旧版；显式重试会重新调用该版本全部片段，可能重复产生调用成本。
4. 旧版本晚完成不允许回退到更低版本。

首版使用 PostgreSQL 精确余弦排序，无 HNSW / IVFFlat 近似索引。SQL 先限制商品、商品有效状态、文档有效版本、READY 和 embedding_space，再排序取 Top-K。similarity 为余弦相似度，不是答案正确概率，也不作为固定拒答阈值。

embedding_space 由接口地址、模型名、维度组成的 SHA-256 标识，防止更换接口后混查不兼容向量。模型和维度当前固定；更换需迁移和重建，不能仅改环境变量。更换接口地址也需新版本索引；已经 READY 的任务不会因重复请求自动重建。

向量接口、检索接口仍限本机开发，admin 路径未接认证；无权限隔离完成声明。当前尚无文档删除接口或召回质量报告。

- 模型协议测试使用本地 HTTP 服务：成功返回、乱序对齐、错误维度、重复 index、零向量、503 有限重试、401 不重试、非法 JSON、缺密钥和超长输入等。
